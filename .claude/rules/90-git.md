# Git & Workflow

**This project is a git repository**, initialised under scoped, explicit owner authorization to
enable the watchOS plan's SDD execution process — a real `.git` and a real `.gitignore` both exist,
and the tree currently carries 27 real commits (root `69c5a39` through the watchOS plan's own work).
The rules below were written before that authorization and speak as though they apply "from the
moment" a repository exists; that moment has passed, and everything below is now live, ordinary
policy — not a hypothetical.

## Never commit on your own
- **Never commit.** Stage the work and stop — a commit happens only when the owner runs `/commit`
- One logical change per commit. A known one-line fix in an unrelated file is deferred to its own
  change rather than folded into the commit at hand, even when it is a live rule violation
- Commit messages are `type(scope): description`, type in `{feat, fix, refactor, style, chore, docs,
  test}`, first line under 72 chars, body wrapped at 72
- **Never** carry `Co-Authored-By`, `Generated by`, a robot emoji, or any AI attribution
- Stage with explicit paths only — never `git add -A`, `git add .`, or `git commit -a`. Use
  `git rm <path>` for deletions
- Never amend a pushed commit, and never pass `--no-verify` or `--no-gpg-sign` unless the owner asks.
  After a failed pre-commit hook the commit did **not** happen — create a new one rather than
  amending the wrong parent
- Before `/commit`, diff `git diff --cached --name-status` against `git diff --name-status`. Do not
  rely on `git status --short` alone
- Run the gate first (rule `85-testing`). A commit of code that has not been through it is a commit
  nobody can report on

## What never enters the tree
- `build/`, `DerivedData/`, `**/xcuserdata/`, `.DS_Store`, `.claude/settings.local.json`
- **Do not ignore `xcshareddata/`.** All four schemes are checked in there as of 2026-09-01 and
  must stay that way. Marking even one scheme Shared writes `SuppressBuildableAutocreation` for
  every target into `xcuserdata/…/xcschememanagement.plist`, so Xcode stops auto-creating the
  others — a scheme with no checked-in `.xcscheme` then simply vanishes from the picker, which is
  exactly how the `WaterBuddy` and `WaterBuddyWatch` schemes were lost (rule `15-project`)
- `CLAUDE.md` and `.claude/**` are committed as files and **never** as members of a build target
  (rule `15-project`)

## Checkpoints
- `HISTORY.md` is **append-only**: new checkpoints at the bottom, and never edit or delete an
  existing entry — even to correct a number that later turned out wrong. Supersede it instead
- A checkpoint is headed `## [YYYY-MM-DD] — <title>`, date only, followed by what changed, the
  rulings it rests on, the files touched and the verification that was actually run
- `tasks/lessons.md` is append-only on the same terms
- Write a doc's git or staging block **last**, after every `git add` the session will make, and never
  write a file or path count you did not just print
